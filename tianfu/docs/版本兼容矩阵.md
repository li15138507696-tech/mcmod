## 四、语义核对（不只是「存在」，还要「行为一致」）

### `UikongqiaoquedingProcedure.execute` 的行为差异

| 版本 | 方法体长度 | 是否转调 `guanbi` | `closeContainer` 时机 | return 偏移 |
|---|---|---|---|---|
| 9.8 | 497 行 | **否**（结算就在本方法内） | 结算**之前** | `[4, 1138]` |
| 10.4 | 17 行 | 是（薄壳） | 结算**之后** | `[4, 26]` |
| 10.20 | 17 行 | 是（薄壳） | 结算**之后** | `[4, 26]` |

### TAIL 注入是否落在正常路径上

Mixin 的 `@At("TAIL")` **只注入到方法内最后一个 `return` 之前**。若方法有多个 return
且正常路径走靠前的那个，钩子就永远不执行——表现是「开窍了但没弹天赋界面、也没标记已结算」，
而且完全不报错。

- 9.8：两个 return 分别是 `4`（`entity == null` 守卫）与 `1138`（末尾正常出口）。
  **TAIL 落在 1138**，正常路径能走到 → OK。
- 10.4 / 10.20：`4`（null 守卫）与 `26`（末尾）。**TAIL 落在 26**，正常路径走到 → OK。

### 9.8 收尾末尾那段 `scoreboard.set(0)` 改的是哪个 objective

9.8 的 `queding` 末尾会对某个 objective 置 0。经核对，objective 名是 **`压力`**，
**不是 `kaiqiao`**。所以它**不会**冲掉 tianfu 刚写入的 `kaiqiao = 1`，门禁不会被误伤。

（这一点很关键：若那一段改的是 `kaiqiao`，9.8 上开窍后 K 键会被永久拦死。）

- 只引用 **4 个**本体类：`GuzhenrenModGameRules`、`GuzhenrenModMobEffects`、
  `GuzhenrenModVariables`、`GuzhenrenModVariables$PlayerVariables`。
- 2 个 Mixin 都注入 `execute`，目标类 `JingJieBaoCunProcedure`（三参）与
  `UikongqiaoquedingProcedure`（两参）三版本都存在且签名一致。
- 转世钩子 `JingJieBaoCunProcedure.execute(Event, LevelAccessor, Entity)`
  **三版本结构完全一致**（1269 行、return 都在 `[4, 2749]`），TAIL 落在末尾正常出口。
- 开窍判定读 scoreboard `kaiqiao`，与天命同口径，跨版本稳定；**不读** `kongqiao`。

**结论：道途无需任何改动即兼容三版本。**

> 附注：道途的客户端类用 `@EventBusSubscriber(modid=..., value=Dist.CLIENT)`（不写 `bus`）。
> 曾怀疑这会让 `RegisterKeyMappingsEvent`（MOD 总线）收不到，但查 NeoForge 加载器
> `AutomaticEventSubscriber` 字节码后确认：它**按每个方法的事件类型推断总线**
> （有 `IModBusEvent` 判断，并打印「Found mix of game bus and mod bus listeners…
> registering them separately」），所以不写 `bus` 是正确写法。

## 八、恶意（guzhenren_malice）1.0.6

恶意**没有 Mixin**，且**不引用任何本体 Java 类**（0 个）——它靠
`data/guzhenren/tags/entity_type/malice_*.json` 与 `data/l2hostility/tags/entity_type/whitelist.json`
这些**数据标签**识别本体妖兽。所以兼容性风险不在字节码，而在**标签里的实体 id 是否还存在**。

### 发现：10.x 合并了 9.8 的蛊修家族

| | 实体注册名总数 | 蛊修相关 |
|---|---|---|
| 9.8 | 699 | `jiang_shi_gu_xiu`、`jiangshiguxiusizhuan` 等 44 个地区性蛊修/蛊师 |
| 10.4 / 10.20 | 656 | 只剩合并后的单个 `gu_xiu` |

10.x 把「南疆 / 北原 / 东海 / 西漠 / 中州」等 44 个男/女蛊修、蛊师 NPC 合并成了
`gu_xiu`（继承 `PathfinderMob`，**不是 Enemy**），而 9.8 的 `JiangShiGuXiuEntity`
继承 `Monster`（是 Enemy）。

`gu_xiu` 继承 `PathfinderMob` 意味着：l2hostility 的挂载条件
`type.is(l2hostility:whitelist) || (e instanceof Enemy && …)` 两条都不满足，
**不手动写进白名单就永远不会被接管**——10.x 上蛊修拿不到难度、头上也不显示等级。

### 1.0.6 的改动

- `malice_normal.json` 增加 `guzhenren:gu_xiu`
- `l2hostility whitelist.json` 增加 `guzhenren:gu_xiu`（94 → 95 条，与分档实体数一致）

**9.8 的僵尸蛊修条目保留**：`jiang_shi_gu_xiu` / `jiangshiguxiusizhuan` 在 10.x 解析不到，
MC 对标签里无法解析的条目**静默跳过**，不报错、不崩。于是形成双向兼容：

| 版本 | 标签里用不上的条目（无害空转） |
|---|---|
| 9.8 | `gu_xiu` |
| 10.4 / 10.20 | `jiang_shi_gu_xiu`、`jiangshiguxiusizhuan` |

这是跨版本标签的**正确写法**：两个版本线各自取自己能解析的那部分。

### 顺手修掉的显示问题

`neoforge.mods.toml` 的 `displayName` / `description` 原本是**双重编码乱码**
（UTF-8 字节被当 GBK 解码，且含不可逆的 `?` 与 CP1252 单字节，无法自动还原），
mod 列表里显示成「铔婄湡浜?脳…」。已按代码真实行为重写为中文。
如需别的措辞，改 `src/main/resources/META-INF/neoforge.mods.toml` 即可。
