# 天意 × 天命 × 道途 兼容性审计（2026-10-27）

> 结论：**三者可以共存**。天意启动时那条 `[天意] 检测到旧附属…` 是**误报**，
> 它只调用 `LOGGER.error`，没有任何禁用、抛异常或卸载逻辑。

## 1. 天意的检测逻辑（javap 实证）

`net.guzhenren.tianyi.TianyiMod` 构造器里：

```java
String[] legacy = { "daotu", "tianfu", "shenshang" };
for (String id : legacy) {
    if (ModList.get().isLoaded(id)) {
        LOGGER.error("[天意] 检测到旧附属「{}」仍在加载：请从 mods/ 删除…", id);
    }
}
```

字节码只有 `ModList.isLoaded` → `Logger.error` → `iinc` 循环，**没有任何副作用**。
所以它是一条纯警告，不构成阻塞。

## 2. 真实冲突面（逐项验证）

| 维度 | 天意 | 天命 | 道途 | 结论 |
|---|---|---|---|---|
| 网络通道命名空间 | `tianyi:*` | `tianfu:*` | `daotu:*` | ✅ 不撞 |
| 注册 id | `tianyi:suminggu` 等 6 个 | `tianfu:*` | `daotu:*` | ✅ 不撞 |
| 命令字面量 | `/tianyi` | `/tianfu…` | `/daotu-chronicle` | ✅ 不撞 |
| 按键 | J（窥天录 / 道途·查看） | K（天命） | M（道途） | ✅ 不撞 |
| 本体的 `qiyun` / `qiyun_shangxian` / `kongqiao` / `GongXianZhi` / `tizhi` | 只 `getfield`（读） | 读+写 | 读+写 | ✅ 天意不改，不抢 |

## 3. 唯一真实共享写点：`shouyuan`

`net.guzhenren.tianyi.world.WillServer` 字节码里存在：

```
116: getfield PlayerVariables.shouyuan:D
134: putfield PlayerVariables.shouyuan:D      ← 天意会写寿元（世界意志的扶持/压制）
```

而天命「命烛残尽（−8）」的语义是**本世寿元不得增加**，`maintain()` 每 tick 封顶。

**这不是 bug，是两套设计的语义冲突**：天意想给寿元，天命说不许。
玩家观感是「世界意志给了寿元但没生效」。

处理方式：天命保持封顶（这是 −8 档的代价，不能让步），但会在检测到天意同时加载时，
在日志里记一条一次性说明，避免以后排查时误判为"寿元系统坏了"。

## 4. 共存操作

1. 三个 jar 同时留在 `mods/` 即可，**不需要删任何东西**。
2. 按键分工：`K` 天命七页 / `M` 道途 / `J` 天意窥天录。
3. 三者都以**希望蛊开窍**为门禁；未开窍时按任何键都只会看到提示，这是设计行为。
4. 天意那条 ERROR 会每次启动都刷一次，属正常噪音，可忽略。

## 5. 未验证

- 天意的 `WillServer` 写寿元的触发频率未知，若每 tick 都写，日志里会看到命烛残尽的封顶提示较频繁。
