## 二、动画名怎么确认的（不是猜的）

对每个候选实体都做了两步硬核对：

1. **读 Renderer / Model 的常量池**，确认它到底加载哪个动画文件；
2. **打开该 `animation.json`，逐个比对 key**。

```
YaotengushitiModel      -> guzhenren:animations/yaoteng.animation.json     keys=[yaoteng]
BaiguiyexingshitiModel  -> guzhenren:animations/baigui.animation.json     keys=[baigui]
JingyueshitiModel       -> guzhenren:animations/jingyueshiti.animation.json keys=[jingyueshiti]
XueyingliuhuatexiaoModel-> guzhenren:animations/xueyingliuhua.animation.json keys=[xueyingliuhua, xueyingliuhuaceshi]
```

寿命 = `animation_length × 20 + 5` tick，沿用 v1.2.23「播完再换」策略；
新增四条全部写进 `lifeOf()`，由 `audit_vfx_anim.py` 的寿命断言逐个校验。

## 三、顺带查清了一件旧事：那些「副作用」到底打在谁身上

1.2.22 的文档只审了**生成路径**（绕过 `finalizeSpawn`），没有审 **`baseTick` 里的 procedure**。
这一版把本体的 tick procedure 反编译读了一遍，结论是**安全**的：

以 `BingXueHuiKanTeXiaoDangShiTiGengXinKeShiProcedure` 为例（当前 3 条道在用）：

```
getEntitiesOfClass(Entity, AABB(位置).inflate(0.5))    // 找身边的玩家
  └ if (e instanceof Player)
       aload 7 (实体自己).teleportTo(player.getX(), ...)   // 把自己挪到玩家脚边，不是挪玩家
...
aload 7 (实体自己) instanceof LivingEntity
  └ addEffect(DAMAGE_RESISTANCE / HEAL / ABSORPTION)      // 给自己上 buff
  └ setHealth(...)                                        // 改自己的血
queueServerWork(n, () -> discard())                        // 到点自我销毁
```

关键是所有 `addEffect` / `setHealth` / `teleportTo` 的接收者都是 **`aload 7` —— 传进来的装饰实体本身**，
不是玩家。所以这些实体挂多久都不会给玩家加 buff、也不会把玩家瞬移。

这也解释了为什么它们放在玩家身边很稳：本体本来就是拿它们当「跟随玩家的特效」用的。

## 七、诚实说明

**游戏内未实测。** 已验证的是：编译、动画名存在、寿命覆盖、实体引用正确、jar 结构与版本一致。

### 需要进游戏确认的

1. **模型大小与锚点**——妖藤/百鬼可能比我估计的大；半径 1.15 / 1.45 是否合适要看一眼。
2. **动画是否真的播**——依赖 v1.2.23 的反射写 `animationprocedure`；若被模块系统挡住，实体仍是静止的。
3. **镜月只有 0.83 秒**，刷新节奏可能显得「闪」；若太快，下一版把它换成更长动画的月相实体。
4. **百鬼与血影流花是一次性动画**（`loop=false`），播完即消失，正好配合「播完再换」。
