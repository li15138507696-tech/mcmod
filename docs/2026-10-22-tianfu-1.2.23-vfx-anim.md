# tianfu v1.2.23 — 让实体真正动起来

> 上一版（1.2.22）接了 4 个本体实体做虚影，但我在文档里承认「动画可能停在默认帧」。这一版把它修好了，而且找到了根因。

## 一、问题：动画为什么不动

本体的这些实体有一个 `ANIMATION` 字段，默认值是字符串 **`"undefined"`**：

```
ANIMATION  'undefined'  TEXTURE  'si_zhuan_fei_jian_'
```

GeckoLib 的控制器拿这个名字去动画文件里找，找不到同名动画就**停在默认帧**——看起来像一尊雕塑。

所以「接上实体」只是第一步，**必须显式告诉它播哪个动画**。

## 二、踩的三个坑

### 坑 1：`ANIMATION` 字段不可访问

试了 `e.getEntityData().set(ANIMATION, "xxx")` —— 编译报错：`无法访问 GeoEntity`。

原因：`getEntityData()` 是 `GeoEntity` 的方法，被设成了 protected。

### 坑 2：`animationprocedure` 也点不出来

发现 `animationprocedure` 是 public String 字段，理论上可以 `e.animationprocedure = "xxx"`。还是报 `无法访问 GeoEntity`。

### 坑 3（真正的根因）：tianfu 的编译 classpath 缺 GeckoLib

前两个坑的错误信息都指向 `GeoEntity`，我一开始以为是字段权限问题。实际原因是：

**本体实体的继承链依赖 GeckoLib 的 `GeoEntity`，而 tianfu 编译时没有 GeckoLib 依赖。**

所以只要代码里出现 `DuochongjianyingshitiEntity` 这个类型，javac 就要解析它的父类链，一碰到 `GeoEntity` 就失败——**跟字段权限完全无关**。

找到 GeckoLib 在 mods 目录（`geckolib-neoforge-1.21.1-4.7.7.jar`），加进探针的 classpath 后，三个探针全部 `exit 0`。

## 三、解法：反射写 `animationprocedure`

因为 tianfu 不能加 GeckoLib 编译依赖（会让附属强依赖 GeckoLib），所以用反射：

```java
private static void setAnimation(Entity e, String anim) {
    Class<?> k = e.getClass();
    while (k != null) {
        try {
            Field f = k.getDeclaredField("animationprocedure");
            f.setAccessible(true);
            f.set(e, anim);
            return;
        } catch (NoSuchFieldException ex) {
            k = k.getSuperclass();   // 字段在父类 GeoEntity 里，必须向上找
        }
    }
}
```

**必须沿继承链向上找**——字段不在实体类自己身上，在 `GeoEntity` 里。

反射在运行期解析，编译期不需要 GeckoLib，所以 `javac exit 0`。

## 五、顺手换掉了一个不可靠的实体

上一版土道用的是 `feishazoushishiti`（飞沙走石），动画名猜的是 `kongbaishiti`。

查证时发现：**飞沙走石既没有独立 `animation.json`，也没有 geo 模型**——它的动画名无法验证，很可能不动。

换成 **`dizhentexiao`（地震特效）**：
- 有独立 `dizhen.animation.json`（动画名 `dizhen` 已验证存在）；
- 有 geo 模型 + renderer；
- 名字里直接带「特效」，本来就是装饰用的；
- 生成 procedure **无副作用**（`danger: NONE`）。

### 还可能失败的环节

1. **反射被模块系统挡住**——NeoForge 的模块化可能对 `setAccessible` 有限制。若日志里出现 `InaccessibleObjectException`，需要改成 Mixin 访问器。
2. **控制器逻辑不认 `animationprocedure`**——我只能确认这个字段存在且被 `getSyncedAnimation()` 读取，但不能 100% 确认控制器就是用它来选动画。若实体仍然不动，下一步是读 `registerControllers` 的字节码。
3. **`dizhen` 动画可能是一次性特效**——地震特效的动画可能是「播一次就停」，配 1 秒寿命可能看不全。

### 下一步可做

- 木道用 `yaotengushiti`（妖藤），有独立动画文件；
- 如果反射真的被挡，改用 Mixin `@Accessor` 访问 `animationprocedure`。
