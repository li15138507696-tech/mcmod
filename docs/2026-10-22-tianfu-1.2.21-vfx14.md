## 二、`Recipe` 从「单粒子」升级成「四层」

原来一个配方只能写一种粒子 + 一种形态，做不出「冲击波 + 符文阵 + 碎石」这种复合画面。

```java
record Recipe(
    ParticleOptions particle,   // 第一层：主环绕
    Shape shape,
    double speed, int phase, int density,
    ParticleOptions rune,       // 第二层：脚下符文阵（可选）
    ParticleOptions accent,     // 第三层：点睛粒子（可选）
    int accentRate,             //   每几次触发
    int shockRate               // 第四层：冲击波每几次触发
)
```

四条道用了全部四层，其余用两到三层。

## 四、模拟图抓到的两个真缺陷

写了 `_crash3/render_vfx14.py`，把每个形态的坐标公式逐帧算出来，画成「俯视 / 侧视 / 单帧」三联图。

### 缺陷 1：血道锁链根本不像缠绕

第一版用 14 颗粒子绕 **3.5 圈**——每圈只有 4 颗，侧视图上粒子排成几排横线，完全看不出螺旋。

修复：
- 圈数 **3.5 → 2.0**（每圈粒子数从 4 提到 10）；
- 密度 **14 → 20**；
- 半径随圈相位正弦起伏（相邻两圈一胖一瘦）。

**教训**：螺旋形态的「圈数」和「密度」必须匹配。一圈少于 8 颗粒子，人眼就认不出是螺旋。

### 缺陷 2：星道粒子全飘在头顶上

第一版 `h = 2.0 + rnd*1.4`（2.0–3.4 格），侧视图一眼看出：**所有星尘都在玩家头顶上方，身体周围空的**。

你描述的是「星辉垂落、星尘洒落」，应该从头顶**落下来**覆盖全身。

修复：`h = 0.2 + rnd*2.2`（0.2–2.4 格），配 `vy = -0.02` 向下速度。

**教训**：所有「环绕身体」的特效，高度范围必须覆盖 0–1.8 格（玩家身高）。只写一个大数就会全飘在头顶。

## 五、性能

四层叠加后，一个玩家的每 tick 广播次数：

| 层 | 频率 | 说明 |
|---|---|---|
| 主环绕 | 每 tick（密集形态）或每 12 tick（其它） | 12–20 粒子 |
| 符文阵 | 每 2 tick | 10 粒子 |
| 点睛粒子 | 每 2–3 tick | 4 粒子 |
| 冲击波 | 每 14–20 tick | 20 粒子 |

最重的是力道（四层全开）：约每 tick 1 次 + 每 2 tick 2 次 ≈ **16 粒子/tick**。

**这是可以接受但需要盯着的数字**。若将来同时有多个玩家开同类特效在同一个区块，或把密度提到 30+，需要重新评估。

|---|---|---|

| 脚下符文阵旋转 | ✅ 双层反向旋转 | 无 |
