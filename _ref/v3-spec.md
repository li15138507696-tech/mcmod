# 天命 1.4.0 规格：可选资质 + 世代递增点数 + 每页分类标签

> 用户已拍板三项：资质用点数买空窍档位、每世基础点递增、每页内加分类标签。
> 本文件是编码阶段的唯一依据。

## 1. 可选资质（资质页不再只读）

### 1.1 新增四个档位条目

| id | 名称 | 品质 | 成本 | 效果 |
|---|---|---|---|---|
| `v2_apt_ding` | 丁等空窍 | 黄 | 1 | `kongqiao = 8` |
| `v2_apt_bing` | 丙等空窍 | 玄 | 3 | `kongqiao = 6` |
| `v2_apt_yi` | 乙等空窍 | 地 | 6 | `kongqiao = 4` |
| `v2_apt_jia` | 甲等空窍 | 天 | 10 | `kongqiao = 2` |

- 语义：**直接设定** `kongqiao`，不是加减。本体约定：甲=2、乙=1/4、丙=5–7、丁=8–10、十绝体=3。
- 四者互斥（同族 `aptitude`），且**与十绝体（`Kind.SIJUE`）互斥**：已选十绝体则不能再买档位，反之亦然。
- 与「空窍桎梏（`v2_aptitude_shackled`）」冲突：买了桎梏就不能买档位（桎梏锁定原资质）。

### 1.2 新增原语

`TianfuTalents.Op` 增加 `APTITUDE_SET`，`arg` 为空，`a` 为目标 `kongqiao` 值。

- 落地位置：`TianfuTalents.applyOnce` / `revokeOnce` 的 switch 各加一个分支。
- apply：`v.kongqiao = fx.a()`；revoke：把 `kongqiao` 恢复为**购买前的原值**（存 `tianfu/v2_apt_prev`，撤销时读回）。
- 若目标字段不可写，抛 `IllegalStateException`，不得静默跳过。

### 1.3 UI 变更

- 删除资质页那条 `"本体资质只读。十绝体与历史机缘记录在本页；旧机缘不再新售。"` 的只读行。
- 资质页顺序：分类「空窍档位」（四个新条目）→「十绝体」→「历史机缘」（只读展示）。
- `hasAnchorSelection()` 必须把「已买空窍档位」也算作有效锚点（否则向导卡住）。

## 2. 每世基础点递增

### 2.1 世代计数

- 键名 `tianfu_generation`，**存在 `PersistentData` 根下、`tianfu` 子标签之外**，因为转世时 `TianfuData.wipeAll` 会删掉整个 `tianfu` 根。
- 在 `JingJieBaoCunProcedureMixin` 调用 `wipeAll` **之前** `+1`，默认 1（第一世）。
- 读不到时按 1 处理，不创建键。

### 2.2 发放规则

选难度时：

```
基础点 = TianfuDifficulty.Option.points() + min(10, (generation - 1) * 2)
```

| 世代 | 顺天应命 | 凡尘问道 | 逆天争命 | 万劫磨道 |
|---|---|---|---|---|
| 第 1 世 | 8 | 6 | 4 | 2 |
| 第 2 世 | 10 | 8 | 6 | 4 |
| 第 3 世 | 12 | 10 | 8 | 6 |
| 第 6 世起（+10 封顶） | 18 | 16 | 14 | 12 |

- 上限 `+10`，与 24 点负面补点上限**互不影响**（补点上限仍是硬 24）。
- 递增只影响**发放**，不改已购条目价格、不改撤销退款。

## 3. 每页分类标签

### 3.1 形式

- 列表顶部（搜索行下方）一排 chip，可横向排布；选中项金色边框 + 高亮底。
- 分类由**现有数据派生**，不新增词条元数据字段。
- 每页第一个 chip 恒为「全部」。

### 3.2 各页分类规则

| 页 | 分类 |
|---|---|
| 难度 | 无分类（只有四档） |
| 出身 | 「地域」「出身」两组 |
| 资质 | 「空窍档位」「十绝体」「历史机缘」 |
| 流派 | 「亲和」（id 以 `qinhe` 结尾）/「大成」（`dacheng`）/「神级」（品质=神 或 极）/「其他」 |
| 体质 | 「负面」（cost<0）/「正面」（cost>0 且非十绝体）/「十绝体」（`Kind.SIJUE`） |
| 心智 | 「修炼」/「念头」/「炼蛊」/「冷却」/「其他」（按 id 关键字） |
| 气运 | 「气运」单组 |

- 切页时保留各页**各自的分类选择**与滚动偏移（与现有 `pageScroll`/`pageQuery` 同机制，新增 `pageCategory`）。
- 分类为空时隐藏该 chip，不显示空分组。
- 搜索与分类是**与**关系：先按分类过滤，再按搜索过滤。

## 4. 硬约束

1. 现有 162 条词条 id 一律不改不删；新增条目用 `v2_apt_*` 前缀。
2. `dahen_`/`daohen_` 前缀保持原样。
3. 不改 `build.gradle`（Veil 那行保留）、`version.properties` 由发布流程统一 bump。
4. Java 源文件 UTF-8 无 BOM，中文不得出现乱码或 `\uXXXX` 字面量。
5. 现有方法签名（7 参数构造器、`refresh`、`refreshV2`）保持不变。
6. 不新增 `[TODO: Agent B]` 标记，本轮交付完整实现。
7. 必须自跑 `gradlew.bat build` 退出码 0。

## 5. 风险（必须在交付里说明）

- 写 `kongqiao` 会影响本体对蛊虫使用与突破的判定，属于跨系统写入，实机未验证前不能宣称安全。
- 世代递增会让老档玩家第一次进游戏时 `generation` 缺失 → 按 1 处理，**不会**补发历史点数。
- 资质档位与十绝体互斥是新增规则，老档若已买十绝体则档位条目应显示为不可购买。
