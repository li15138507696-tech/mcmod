# 道途附属 v1.3.1 — 界面优化与美化

> 承接 v1.3.0 肉鸽抽选系统。这一版**只改界面**，玩法数值、属性落地、存档结构一概未动。

## 一、这一版改了什么

### 1. 成长页重做：从「一堆文字」变成「一眼看懂」

v1.3.0 的成长页是纯文字列表，池进度、抽次、档位、特殊奖励进度全靠读字。这一版把它们抽成**固定头区**：

```
历练池  ████████████████████░░░░░░  187.3 / 240.0
[第 13 抽 · 3 档] [三转 ×1.96]        特殊 ●●○○○○○○○○
点开抽选记录可换选 · 不限次数、永不叠加
```

- **历练池进度条**：6px 高，带底槽；攒满时填充转鎏金并加描边，一眼看出「能抽了」。
- **两个徽标**：抽次 + 档位、转数 + 缩放倍率。转数 ≥3 时转数徽标变鎏金。
- **特殊奖励 10 个进度点**：`draws % 10` 点亮，抽满一轮时全亮。

做成**固定头区**而不是列表行，是因为玩家往下翻属性时也必须能看见「还差多少能抽」——这是这一页最需要盯的数字。

### 2. 抽选记录：从「盲点循环」变成「展开挑选」

v1.3.0 点一下记录行就切到**下一个**候选，玩家既看不到还有哪些选项，也不知道切到了第几个。

现在改成展开式：

```
▾ 第 12 抽   速度 +1.0%                          收起
    ◉ 力量   +3.0%        ← 当前选中（鎏金 + 高亮底）
    ○ 生命   +3.0%
    ○ 速度   +1.0%
    ○ 幸运   +0.50
    ○ 护甲韧性 +0.30
```

- 点记录行 → 展开 / 收起（**不发网络包**）。
- 点候选行 → 才发 `DaotuPickPayload` 换选。
- 候选行高 16px（比常规 20px 矮），视觉上从属。
- 展开态记在 `expandedDraw`，由 `buildRows()` 重建，滚动 / 刷新不丢；记录消失（转世）时自动收起。

### 3. 属性行加横向进度条

纯数字看不出「这项算多还是算少」。现在每项属性都有条，长度按**软上限**归一化：

```
力量      ████████░░░░░░░░░░░░  +42.0%
生命      ██████░░░░░░░░░░░░░░  +30.0%
击退抗性  ████████████████████  +1.00   ← 顶上限，转鎏金
```

无软上限的属性（力量 / 生命 / 速度 / 攻速 / 幸运…）用饱和函数 `v/(v+k)`：永远不溢出，前期涨得快、后期涨得慢，不会「一直满格」。

### 4. 道途总览页改键值对 + 点线

原来是一长串 `势力：血道 · 档位 内门` 的拼接句。现在：

```
本局
第几世  ········································  第 3 世
已抽次数 ·······································  12 次
本体转数 ·······································  三转 ×1.96
势力
所属    ········································  血道
档位    ········································  内门 · 观察期
```

左灰键、右亮值、中间点线牵引，键名长短不一时也不会串行。

### 5. 势力页加贡献进度条

每个档位行底部一条 2px 细线，显示 `gongxian / threshold`。已达档位用鎏金，未达用朱砂。

### 6. 页签与面板

- 活动页签：朱砂底 + 鎏金下沿 + 顶部暗金 + 下方小三角指向内容区。
- 非活动页签 hover 变亮，底部一条极淡的线，四个签看起来是一排。
- 面板加左右两道极淡竖纹暗影，大块面板不至于太空。
- 页脚按页签显示不同内容：成长页显示「下一抽预期收益」（如 `下一抽 · 3 档 · 力量约 +4.9%`），其余页签显示页签名。

## 二、模拟图暴露并修掉的三个真缺陷

这一版引入了一个离线渲染器 `_crash3/render_mock.py`：按源码里的坐标公式逐像素复刻界面，直接出 PNG。它暴露了三个**静态审计看不出来**的问题：

### 缺陷 1：面板在 GUI scale 3 下戳出屏幕

原代码 `int y = height / 2 - 118` + `listBottom = height / 2 + 108` 是**固定偏移**。

1920×1080 + GUI scale 3 → 逻辑分辨率只有 **640×360**，面板总高约 340px，`y = 180-118 = 62`，底边 `62+16+6+44+2+190+24 = 344` —— 逼近 360，边距只剩 16px；而在更矮的屏幕（如 1366×768 scale 3 = 455×256）会**直接戳出底边**。

修复：`layout()` 改成**自下而上累加**再整体居中：

```java
int chrome = tabH + catH + heroH + footH;
int avail  = height - chrome - 16;
int listH  = Math.max(ROW_H * 3, Math.min(LIST_H, avail));
int y      = Math.max(8, (height - (chrome + listH)) / 2);
```

面板宽度也自适应：`panelW = Math.min(PANEL_W, width - 16)`。

### 缺陷 2：滚动的半露行画到页脚上

`drawRows` 只跳过**完全**在视口外的行，半露的行用**未裁剪**的 `y0` 绘制，于是最后一行会画到页脚上、和「M 关闭」叠字。

修复：加 `g.enableScissor(...)` / `g.disableScissor()`，且所有行改用裁剪后坐标 `cy0` 绘制。

### 缺陷 3：内容溢出时没有任何视觉提示

加了 scissor 之后，被切掉的那半行看起来像渲染坏了。修复：加 `drawScrollHints`——上下两端各一条 13px 渐隐带 + `▲`/`▼` 箭头。箭头画在渐隐带**内部**，不压第一行文字。

## 五、不变的铁律（这一版全部守住）

- `layout()` 仍是**唯一**分配命中区的地方，`render` 只读。
- 渲染顺序与命中测试顺序一致。
- 虚拟列表：只画可见行，`ROW_H` 固定。
- **绝不调 `super.render()`**（会触发 `renderBlurredBackground` 全屏模糊）。
- 无贴图，全部 `g.fill` / `drawString` 自绘。
- 所有行文字过 `fit(s, maxW)`，超宽裁 `…`。
- 之前的 3 处重叠修复未回退。

## 七、诚实说明

**游戏内未实测。** 上述结论全部来自：

1. `javac` 编译通过（34 源文件，exit 0）；
2. 静态审计脚本（29 + 47 + UI + 回归，全绿）；
3. 字节码验证（确认无模糊调用）；
4. **离线渲染模拟图**（`_crash3/mock_growth_scale3.png` 等 6 张）。

模拟图用的是 Windows 微软雅黑 9px 近似 MC 默认字体，像素宽度按 CJK 9 / ASCII 6 / 空格 4 估算，**不是真实 MC 字体渲染**。真实游戏里的字形宽度可能有一两像素差异，若某行文字偏挤，`fit()` 会裁成 `…` 而不是压字——但排版观感需要你进游戏确认。

头区高度 `HERO_H = 44` 是按「2 + 14 + 13 + 9 = 38px 实际需要」留了 6px 余量算出来的；若真实字体行高大于 9px，第三行提示文字可能贴边。
