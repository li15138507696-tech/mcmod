> 版本：**1.3.0**（玩法大改，minor bump）
> jar：`daotu-1.3.0.jar`，107,663 字节
> SHA256：`93C99D568CBE7E74DDDE452DB3F60FA11DD820C691964984C55002DF045CD3D2`
> 状态：静态审计 47/47 通过；**游戏内未实测**

---

## 一、这一版改了什么

1.2.1 的成长是「16 路流派 × 6 阶」，每路各记一份历练账，攒到门槛自动升阶、按阶发表格加属性。
问题有三：

- **只有 16 个维度**，且每路每阶加什么、加多少都是写死的，玩到后期没有新鲜感；
- **阶位有天花板**（6 阶），撞顶之后历练就白攒了；
- **玩家没有选择权**——升到哪一阶、拿到什么，全是表格决定的。

1.3.0 换成**肉鸽式抽选**：历练不再按路分账，只汇成一个池；池满就抽，抽到 5 个候选里**自己挑一个**；属性种类扩到 14 项，**不设等级、不设上限**（少数几项受引擎硬墙约束），每次给的值随本体转数放大。每 10 抽额外给一次特殊奖励。

---

## 二、核心循环

```
击杀 / 游历 / 修炼
        │  累积历练
        ▼
   历练池 ≥ 240
        │  自动抽选（不打断战斗）
        ▼
   5 个候选，随机先发 1 个
        │  记进 run/pending
        ▼
   按 M 打开界面 → 点一行 → 换选（不限次数，永不叠加）
```

- **阈值恒定 240**，不随抽次上涨。抽得越多不会越难，纯粹是「攒得久抽得多」。
- **抽选不消耗操作**：池满自动发，玩家该打怪打怪。想调整就事后在界面里换。
- **换选不叠加**：换的时候先撤销旧候选、再叠加新候选，同一次抽永远只有一个生效。

### 每 10 抽的特殊奖励

第 10、20、30… 抽，在正常那次之外**额外**给一次：

- **3/5 概率**：从 12 个正向 buff 里抽一个，**整局常驻**（`DaotuBuffs.maintain` 每秒续期，因为本体在四气 buff 到期时会 `removeAllEffects()` 清空全部效果）；
- **2/5 概率**：给 **100 点道痕**（× 转数缩放），记进 `run/ledger`。

特殊奖励**不给属性**——属性走常规抽选，特殊只负责「质变」。

## 三、数值表

### 常规抽选（5 档递减）

| 抽次 | 力量 | 防御(韧性) | 生命 | 速度 | 抗性 | 其他 |
|---|---|---|---|---|---|---|
| 1–5 | 3.0% | +0.5 | 3.0% | 1.0% | 1.0% | +0.5 |
| 6–15 | 2.5% | +0.4 | 2.5% | 0.8% | 0.8% | +0.4 |
| 16–30 | 2.0% | +0.3 | 2.0% | 0.6% | 0.6% | +0.3 |
| 31–60 | 1.5% | +0.2 | 1.5% | 0.4% | 0.4% | +0.2 |
| 61+ | 1.0% | +0.1 | 1.0% | 0.3% | 0.3% | +0.1 |

**为什么递减**：不设等级上限，如果每抽都给固定值，几百抽之后数值会失控。递减让「前期涨得快、后期靠量堆」，曲线更平滑。

### 转数缩放

```
实际值 = 表值 × 1.4^(转数 - 1)
```

| 转数 | 倍率 |
|---|---|
| 一转 | ×1.00 |
| 二转 | ×1.40 |
| 三转 | ×1.96 |
| 四转 | ×2.74 |
| 五转 | ×3.84 |

转数从本体 `PlayerVariables.zhuanshu` **只读**，本插件从不写它。转数越高，同样一抽给得越多——这是「本体修为带动附属成长」的口径。

### 14 项属性

| 键 | 中文 | 语义 | 软上限 |
|---|---|---|---|
| `attack_damage` | 力量 | 百分比 | 无 |
| `max_health` | 生命 | 百分比 | +200% |
| `movement_speed` | 速度 | 百分比 | +100% |
| `attack_speed` | 攻速 | 百分比 | +150% |
| `armor_toughness` | 护甲韧性 | 平加 | 无 |
| `max_absorption` | 伤害吸收 | 平加 | 无 |
| `knockback_resistance` | 击退抗性 | 平加 | 1.0 |
| `fall_damage_multiplier` | 摔伤倍率 | 平加（负=减免） | 无 |
| `luck` | 幸运 | 平加 | 无 |
| `safe_fall_distance` | 安全摔落 | 平加 | 无 |
| `attack_knockback` | 攻击击退 | 平加 | 无 |
| `oxygen_bonus` | 水下呼吸 | 平加 | 无 |
| `step_height` | 跨越高度 | 平加 | +2.0 |
| `scale` | 体型 | 百分比 | +100% |

**「不设上限」的例外**：`scale`、`step_height`、`knockback_resistance`、`movement_speed`、`attack_speed`、`max_health` 六项有软上限——不是设计取舍，是引擎墙（体型过大会穿模、移速过快会出服务端校验、生命值过高会让客户端血条溢出）。其余 8 项真正无上限。

### 两个关键工程决策

**力量/生命必须用 `ADD_MULTIPLIED_TOTAL`，不能平加。**
1.21.1 原版基础攻击力 = 1.0、基础生命 = 20。若按平加 +0.5 攻击力，两次抽选就把伤害翻倍；抽 20 次是 11 倍。改成百分比层后，3% 就是 3%，不会失控。

**防御不走 `armor`，走 `armor_toughness` + `max_absorption`。**
本体有 **46 个 procedure** 用 `/attribute ... generic.armor base set N` 控制护甲（铁皮蛊、铜皮蛊那一类）。`base set` 会覆盖基础值但**不会删除 modifier**——如果本插件在 `armor` 上挂 modifier，玩家开蛊时白赚一层、本体卸甲后加成还留着，两边打架。改用 `armor_toughness` 完全避开：本体只有 1 处碰它，且是「低于 15 才抬到 15」，与 modifier 兼容。

## 四、属性怎么落地

`run/attrs` 存「键 → 值」，每次变化都**全量重建**：

```
清掉 14 个 daotu:run_* modifier
   → 按 run/attrs 重新挂上
```

不做增量更新，是因为本体有 205 个类在调 `setBaseValue`，增量维护迟早会因为某处重置而错位。全量重建每次从当前真值出发，天然幂等。

**转世清空**：寿元耗尽时按 7 步固定顺序结算——

1. 读 `run/ledger`（本局发出去的道痕）；
2. 逐项 `subDaohen` 扣回（`max(0, …)` 兜底，绝不扣成负数）；
3. `DaotuData.wipeAll` 清空整个 `daotu` 标签；
4. `DaotuRun.beginRun` 重建空局（局号 +1）；
5. `markApplied`；
6. `DaotuAttributes.sync`（把 modifier 全撤）；
7. 播报「本局 N 次抽选的属性已清空，道痕已扣回」。

第 3、4 步顺序不能反（先清再建）；第 1、2 步必须在第 3 步之前（清完就读不到了）。

## 五、旧存档兼容

| 存档版本 | 折算方式 |
|---|---|
| 1.0.0（有「出身」） | 按出身强弱给 4 / 8 / 12 次抽选 |
| 1.1.0–1.2.1（有 16 路阶位） | 按最高阶给 0 / 4 / 8 / 12 / 16 / 20 次 |
| 全新 | 0 次，从零开始 |

折算走 `DaotuDraw.replayForMigration`：每次把池填到刚好够一次、再走**正常抽选流程**。这样档位、转数缩放、第 10/20… 抽的特殊奖励全部按真实规则结算，不会出现「迁移来的属性跟正常抽的不一样」。

**历史道痕不追溯扣回**：v1 阶位奖励发出去的道痕就留给玩家。只有 v2 之后抽出来的才记进 ledger、转世时扣。

## 八、构建期修掉的两个坑

**1. `javac` 不删旧 class → jar 里带着已删的类。**
删掉 `DaotuGrowth.java` 后重新编译，`javac_out` 里 10 个 `DaotuGrowth*.class` 还在，`pack_jar.py` 照单全收，jar 变成 133,923 字节（正确是 107,663）。已在 `javac_check.py` 里加「编译前清空输出目录」。
**这个坑很隐蔽**：源码里 grep 不到任何引用、编译零错误，但 jar 里就是多出几个类。以后删任何源文件都要留意。

**2. 审计脚本两处子串误报。**
- `"armor" in 源码` 会命中注释里的 `ARMOR` 和 `armor_toughness`；
- `"DaotuGrowth" in jar 条目` 会命中**仍在用的** `DaotuGrowthApply.class`。

都改成精确匹配（跳过注释行、正则 `DaotuGrowth(\$[^/]*)?\.class$`）。
