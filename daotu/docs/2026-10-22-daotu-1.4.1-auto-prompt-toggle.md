# 道途附属 v1.4.1 — 自动弹窗开关

> 承接 v1.4.0。这一版只解决一件事：**攒满历练时不再强行把界面糊到玩家脸上**。

## 一、你要的改动

| 你的反馈 | 本版实现 |
|---|---|
| 杀个怪，升级界面直接弹出来 | 页脚加了「自动弹窗 开/关」开关，**关掉后只在聊天栏提示一次**，不再弹窗 |
| 不选完还不能关界面 | 关掉后再也不会被重新顶出来；即使开着，关掉面板后也不会因为继续攒历练而反复弹 |

## 二、为什么以前像「关不掉」

v1.4.0 的流程有两处会弹窗，第二处是元凶：

1. 攒满 → `tryDraw()` 生成候选 → `DaotuNet.promptChoice()` **强制弹窗**（合理，这是升级时机）；
2. **只要还有待选候选**，每次涨历练再调 `tryDraw()` 都会走
   `if (offer 非空) promptChoice()` → 又是强制弹窗。

历练是打怪 / 走路 / 打坐三路一起涨的，所以玩家按 ESC 关掉面板、走两步，面板立刻又回来了——
看起来就像「不选完不给关」。其实 ESC 一直是能关的，只是关不干净。

**本版改法**：
- 第 2 条分支从 `promptChoice()` 改成 `sendState()`（只刷新已开着的界面）；
- 弹窗只发生在「刚攒满、刚生成候选」那一次。

## 三、开关怎么工作

### 3.1 开关在哪

道途界面（按 M）**页脚右侧**、`M 关闭` 左边：

```
┌──────────────────────────────────────────┐
│ 击杀 · 游历 · 修炼 皆积历练   [自动弹窗 开 ◉] M 关闭 │
└──────────────────────────────────────────┘
```

- 点一下切换，带按钮音效；
- 文字直接写「开 / 关」，不用靠滑块颜色猜；
- 悬停时边框变金色。

### 3.2 值存在哪

`daotu/autoPrompt`（**不在 `run` 里**）。

放根标签而不是 `run`，是因为 `run` 会在转世时整个重建；界面偏好属于「玩家习惯」，
不该跟着转世一起重置。老存档没有这个键 → 按**开**处理，升级后行为不变。

### 3.3 服务端说话算数

```
点击开关
  ↓ C2S  DaotuSettingPayload(autoPrompt)
服务端  DaotuRun.setAutoPrompt()  →  DaotuNet.sendState()
  ↓ S2C  DaotuStatePayload(..., autoPrompt)
界面    用服务端回推的值重画（不长期信任本地乐观翻转）
```

弹窗是服务端 `promptChoice()` 决定的，所以开关必须存在服务端；
只改客户端标志的话，服务端照样发 `open = true`，开关等于没做。

### 3.4 关掉之后

攒满时：

- 不弹窗；
- 聊天栏一条：`[道途] 历练已满，按 M 打开道途选择升级`；
- 候选**不会丢**（本来就不扣池，扣池发生在 `choose()`），随时按 M 继续选。

## 四、改动清单

| 文件 | 改动 |
|---|---|
| `DaotuRun` | 新增 `autoPrompt()` / `setAutoPrompt()`，读写 `daotu/autoPrompt` |
| `DaotuNet` | `promptChoice()` 按开关分流：弹窗 / 只推状态 + 聊天提示 |
| `DaotuDraw` | 「已有待选」分支改为 `sendState()`，不再反复强制弹窗 |
| `DaotuSettingPayload`（新） | C2S `daotu:setting`，一个 boolean |
| `DaotuStatePayload` | 末尾新增 `autoPrompt` 字段，界面据此显示开关 |
| `DaotuMod` | 注册新包；协议号 `1 → 2`（状态包结构变了，避免新旧端解码错位） |
| `DaotuViewScreen` | 页脚开关：布局命中区、绘制、点击、音效、状态同步 |

## 六、已知取舍

- **默认还是「开」**：v1.4.0 的老玩家升级后不会发现行为变化；想静音的人自己去关。
- **关掉后没有二次提醒**：攒满只提示一次，之后不再刷屏；候选一直在，按 M 就能看到。
- **多人服各自独立**：存在玩家 NBT 里，不是全局配置，服主不用统一改。
