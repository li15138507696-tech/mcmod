# 道途 · 十六路流派成长（v1.1.0）

> 替代 v1.0.0 的「出身」系统。v1.0.0 让玩家在开局选一个**先天**身份，
> v1.1.0 把它彻底换掉：没有出身，只有**后天挣来的十六路阶位**。
>
> 最后更新：2026-10-21 · 版本 1.1.0 · 游戏内未实测

---

## 一、为什么推倒「出身」

v1.0.0 的出身有三个结构性毛病：

1. **语义相悖**。「出身」是先天的一次性选择，而蛊界修行的核心叙事是「后天夺来」——
   凡人靠杀伐、游历、苦修往上爬。开局点一个出身，等于把整条成长线跳过了。
2. **锁死流派**。16 个出身各自绑定一个势力/流派，选完就定了，没法「先练力再转剑」，
   也没法「偏科」。而蛊界恰恰盛行多修与改修。
3. **占掉界面一格**。成长页原本是一条 16 级的单阶梯，所有玩家走同一条线，
   除了数字大小没有任何区别。

v1.1.0 改成：**十六条流派各有一条六阶成长路线，历练值分别积累，升阶各发各的奖。**

## 三、历练怎么来

三种来源，**每次获得都同时推进全部十六条路线**，只是各路吸收系数不同。

### 3.1 战斗

| 事件 | 历练 | 上限 |
|------|------|------|
| 击杀生物 | `最大生命 × 0.8` | 单次 400 |
| 受到伤害 | `伤害 × 0.5` | 单次 30 |

杀强敌给得多，杀鸡给得少。受伤给零头，鼓励硬碰硬而不是永远风筝——
但上限压到 30，防止「故意挨打刷历练」。

### 3.2 游历

| 事件 | 历练 |
|------|------|
| 水平位移 | 每 24 格 1 点 |
| 首次进入新群系 | 一次性 +25 |

只算水平距离（竖直方向多半是电梯或摔落）。单次采样位移超过 60 格、
或纵向超过 200 格，判定为传送，**记 0**——这是防瞬移刷的核心。

### 3.3 修炼

每 12 秒 1 点，**打坐翻倍**（潜行 + 静止 + 站在地面）。

## 四、吸收系数（偏科的由来）

同一份历练，各路线各取多少：

```
战系（力/剑/火/雷/血/毒/骨/魂/金）：战斗 ×1.2~1.5，游历/修炼 ×0.6~0.9
修系（律/水/云/月/智/炼/宙）    ：战斗 ×0.7~1.0，游历 ×0.9~1.5，修炼 ×0.8~1.5
```

极端对比：同样打一场硬仗，**力道**拿 `战斗 ×1.5`，**智道**只拿 `战斗 ×0.7`——
差了 2.14 倍。反过来坐一炷香，**智道** `修炼 ×1.5`，**力道** `修炼 ×0.6`。

于是不需要「选流派」，玩家的行为自然塑造主修方向。这也正是「道途」二字的本意。

## 五、六阶与奖励

每条路线六阶，门槛统一：

| 阶 | 门槛历练 | 道痕 | 属性 | buff |
|----|----------|------|------|------|
| 0 | 240 | +200 | 小幅 | — |
| 1 | 840 | +300 | 小幅 | — |
| 2 | 2000 | +400 | 中幅 | — |
| 3 | 4200 | +350 | 中幅 | — |
| 4 | 8400 | +490 | 大幅 | 有（600~2400 tick）|
| 5 | 16000 | +700 | 大幅 | 有（3600 tick）|

> **v1.2.1 获取难度 ×2**：门槛从 120/420/1000/2100/4200/8000 翻倍为
> 240/840/2000/4200/8400/16000。
> **只动门槛，不动奖励**——每阶给的道痕、属性、buff 一律不变，
> 所以每一阶都变得更值钱，而不是奖励缩水。历练吸收系数也不变，
> 玩家看到的分档（战系偏战斗、修系偏游历修炼）依然成立。
>
> 翻倍后的实际节奏（`sim_difficulty.py` 按源码常量推算）：

| 阶 | 门槛 | 战斗型（力道×1.5） | 游历型（云道×1.5） | 修炼型（智道×1.5） |
|----|------|-------------------|-------------------|-------------------|
| 0 | 240 | 10 只怪 | 3,840 格 | 0.3 小时打坐 |
| 1 | 840 | 35 只怪 | 13,440 格 | 0.9 小时 |
| 2 | 2000 | 83 只怪 | 32,000 格 | 2.2 小时 |
| 3 | 4200 | 175 只怪 | 67,200 格 | 4.7 小时 |
| 4 | 8400 | 350 只怪 | 134,400 格 | 9.3 小时 |
| 5 | 16000 | 667 只怪 | 256,000 格 | 17.8 小时 |

（「只怪」按 20 血普通怪算，每只 16 原始点。游历型走 24 格得 1 原始点。）

> **v1.2.0 后期道痕 −30%**：第 3~5 阶原为 500 / 700 / 1000，实测推演发现
> 满级单路 3500 点、十六路合计 49600 点，远超本体设计承载（本体单条道痕通常以
> 数百为量级）。现降为 350 / 490 / 700，后期（3~5 阶）合计从 35200 → 24640，
> 正好 −30%；前期（0~2 阶）保持 200 / 300 / 400 不变，让新手期仍有明显正反馈。
> 满级十六路总道痕 49600 → 39040。

**晋升全自动**：历练够了立刻升阶，不需要手动点「领取」。
奖励**逐阶补发**——中间跳过几阶也一个都不会少（`claimUpTo` 从上次结算点线性补到目标阶）。

### 5.1 三类奖励

1. **道痕**：写本体的 `daohen_*` / `dahen_*` 字段。道痕是蛊界一切数值的总开关，
   涨了之后真元上限、蛊虫威力、体质判定全都跟着走。
2. **属性**：走 `daotu:` 命名空间的 AttributeModifier，共八类——
   `health`（生命）、`attack`（攻击）、`attack_speed`（攻速）、`speed`（移速）、
   `knockback_resist`（击退抗性）、`fall`（摔落减免）、`qiyun_cap`（气运上限）、
   `knockback`（击退加成）。
   全部由 `DaotuApply.growthAttr()` 汇总**所有已达成阶位**后一次性套用，
   与本体/tianfu 的修饰符互不覆盖。
3. **buff**：本体真实存在的 effect，按注册表 id 解析。
   - 战系用 `guzhenren:lvdaozengfu`（力道增幅）、`jiandaoshanghaizengfu`（剑道伤害增幅）、
     `yandaozengfu`（炎道增幅）、`leidaozengshang`（雷道增伤）等。
   - 修系用 `shuidaozengfu`、`yudaoguchongweilizengfu`、`qidaoguchongweilizengfu`、
     `jindaozengfu`、`weilizengjia`（威力增加，通用）。

   > **只用了本体确证的 9 个 id**。`audit_growth.py` 会打开本体 jar 的
   > `GuzhenrenModMobEffects.class` 逐个核对常量名，编造 id 会直接 FAIL。
   >
   > 解析不到时**静默跳过**（只打 debug 日志），本体换版本删了 buff 也不会让升阶崩掉。

### 5.2 buff 不能只发一次（v1.2.0 修复）

本体 `SiqibuffXiaoGuoChiXuShiMeiKeFaShengProcedure` 在「四气 buff」到期时会对
`LivingEntity` 调用 **`removeAllEffects()`**——那是清空**全部**效果，不区分来源。
所以「升阶时发一次 buff」这个做法是错的：玩家只要身上有四气 buff 到期，
道途发的流派增幅就会被一起抹掉，而且**玩家完全看不出原因**。

对策（`DaotuBuffs`）：不依赖一次性发放。

| 时机 | 行为 |
|------|------|
| 升阶瞬间 | `grantNow()` 立即发一次，玩家马上看到反馈 |
| 每秒 | `DaotuRuntime` 调 `maintain()`，按当前阶位检查应有的 buff，缺了就补 |

续期细节：

- 时长 12000 tick（10 分钟），剩余 > 200 tick 时不动，避免图标每 tick 闪。
- 玩家自己喝的同名药水**不被覆盖**：已有时长更长时直接跳过。
- 本体用 `-1` 表示无限时长；遇到无限就不动它（避免把玩家的无限 buff 改成有限）。

## 六、防刷设计

| 面 | 措施 |
|----|------|
| 刷怪 | 单次击杀历练封顶 400 |
| 挨打 | 单次受伤封顶 30 |
| 瞬移 | 单次采样位移 >60 格（水平）或 >200 格（竖直）记 0 |
| 挂机 | 修炼按秒节流，`DaotuRuntime` 每 20 tick 调一次 |
| 重复进群系 | 群系 id 记在 `biomes` 串里，进过的只给一次 |
| 死亡复制 | 只在服务端主线程调用，无并发问题 |

所有历练状态存在玩家 `PersistentData` 的 `daotu` 子标签，**不写本体的 `PlayerVariables`**
（除了道痕奖励那一步，那是刻意要写进本体的）。

## 七、存档结构

```
daotu (compound)
  lilian      compound  十六路历练值 {lvdao: 1200.0, lidao: 800.0, ...}
  rank        compound  十六路当前阶位 {lvdao: 3, lidao: 2, ...}
  claimed     compound  十六路已结算到的阶位（-1 = 未结算）
  migrated    bool      旧「出身」存档已折算
  origin      String    旧字段，仅迁移时读，读完清空
  faction     String    当前势力 id（空串 = 未入势力）
  tier        int       当前档位 0..5
  tierMax     int       历史最高档位（只增不减，转投不清）
  switchAt    long      转投时间戳（观察期判定）
  nodes       list<str> 已点节点 "大类:层号"
  awakening   String    觉醒分支 "大类:A|B"
  applied     bool      本世开窍已结算
```

## 八、旧存档迁移

v1.0.0 玩家选过出身的，登录时自动折算（幂等，靠 `migrated` 标记）：

| 旧出身 | 折算起点阶 |
|--------|-----------|
| `xiongjia_kuangtu` / `zuitu` / `tianwai_yigu` | 第 1 阶 |
| `baijia_liehu` / `shangdui_yigu` / `guyue_pangzhi` / `dushi_fang` / `guyue_dixi` / `baijia_shaozhu` / `lianxuan_xuetu` / `jianmen_zhujian` / `bingxue_waimen` / `sanxiu` | 第 2 阶 |
| `hundao_yishi` / `daoyou` / `qiankun_sanyi` | 第 3 阶 |

**十六条路线统一折到同一阶**，并把 `0..rank` 标记为已结算——
旧出身已经发过元石/人气/道痕，不能重复发。
最高只折到第 3 阶：否则老玩家一上来就接近顶阶，把整条成长线跳过去了。

## 九、身份头衔

「身份:」那一行取**阶位最高的那条路线**作主修（并列时取阶内历练更多的），
格式 `主修阶名·档位`，例如「剑主·内门」。观察期内后缀换成「（转投观察期）」。

主修**只影响显示**，不影响任何数值——十六条路线的加成各自独立累加，
玩家可以十六路并进，没有「只能主修一个」的限制。

## 十、与另两条进度线的关系

道途界面共四页，三条进度线**互不干扰**：

| 页 | 进度线 | 驱动 |
|----|--------|------|
| 成长 | 十六路阶位 | **历练值**（打/走/坐） |
| 流派树 | 六大类 42 节点 + 12 觉醒 | **感悟点**（道痕和 ÷ 1500） |
| 势力 | 六档 + 转投 | **本体贡献值**（只读，不消耗） |
| 总览 | 汇总 | — |

**刻意不让「道痕总量」当成长驱动**：道痕是流派树的感悟点来源，
如果成长也吃道痕，两条线会互相挤占，玩家就得在「升阶」和「点树」之间二选一。
用独立的历练值，两条线可以并行推进。

## 十一、数值平衡说明

- 新号从第 0 阶起步，第 0 阶门槛 240 点（v1.2.1 翻倍前为 120）。
  按「杀一只 20 血僵尸 = 16 点 × 力道 1.5 = 24 点」算，约 10 只怪到第 0 阶；
  按修炼算约 0.3 小时。这是**故意**的：第一步要能在一局游戏内看到，
  翻倍后仍在「一局内可见」的范围内。
- 顶阶 16000 点（翻倍前 8000）。纯打坐型玩家约 17.8 小时到顶阶，
  纯战斗型约 667 只怪；实际游玩三者混着来，远快于此。
  十六条全满需要更长——这是长线目标，不是一季度的内容。
- 吸收系数区间 0.6~1.5，最偏科的两条相差 2.14 倍。
  刻意不做成 0.1~3.0 那种极端：那会让「非主修路线永远长不起来」，
  等于变相锁死流派，与设计初衷相悖。

## 十二、已知限制

- **游戏内未实测**。所有数值、布局、注册表解析都是静态核对的结论。

  v1.2.0 对「升阶播报 / buff 挂载 / 属性叠加」三项做了静态复核，结论如下
  （**仍非游戏内验证**，只是把「代码是否真的会执行到」这条链路查透了）：

  | 项 | 静态结论 | 依据 |
  |----|----------|------|
  | 升阶播报 | 会执行，且已改分档 | `award()` → `announce()`；`displayClientMessage` 签名核对 |
  | buff 挂载 | **原来靠不住，已修** | 本体有四气 `removeAllEffects()`；改为每秒 `maintain()` 兜底 |
  | 属性叠加 | 会叠加，但有一项**原来漏挂** | 本体 0 处 `removeModifier`；`K_KNOCKBACK` 原先无消费点，已补 `ATTACK_KNOCKBACK` |

  首次进游戏仍应重点验：升阶播报的显示位置（动作栏 vs 聊天栏）、
  四气 buff 到期后道途 buff 是否在 1 秒内恢复、属性面板数值是否等于本体 + 道途。
- 客户端与服务端的十六路快照走 `DaotuStatePayload`（`int[16]` + `double[16]`），
  网络开销约 200 字节/次。**升阶推送不再强制弹界面**：`open` 字段区分
  「玩家按 M 请求」与「服务端主动刷新」，后者只在界面已开时原地刷新。
- 本体若改 `GuzhenrenModMobEffects` 的字段名，`audit_growth.py` 会第一时间 FAIL。
