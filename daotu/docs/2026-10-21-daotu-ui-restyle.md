# 道途界面「糊」的成因与画风改造

- 日期：2026-10-21
- 涉及：`client/DaotuViewScreen.java`、`client/DaotuClientHandler.java`
- 版本：1.1.0 起，成长页由「16 级单阶梯」改为「十六路流派」，本文第 5 节的
  出身行相关内容已同步改写为成长路线行

---

## 1. 「糊」的两个真实原因

### 原因一（主因）：`super.render()` 触发全屏模糊

原 `render()` 把 `super.render(g, mouseX, mouseY, partialTick)` 放在**最后一行**，以为只是「收尾」。但父类实现的第一步就是画背景：

```
Screen.render(GuiGraphics, int, int, float)
  → renderBackground(GuiGraphics, int, int, float)
      → renderBlurredBackground(float)
          → GameRenderer.processBlurEffect(float)   // 全屏高斯模糊
          → RenderTarget.bindWrite(false)
      → renderMenuBackground(GuiGraphics)
```

后果：自己刚画好的面板、文字，**全部被模糊层盖住**。看起来就是「糊」。

修复：`render()` 里**不再调用 `super.render()`**，改为自己调用
`renderBackground(...)`，并把 `renderBackground` 覆写成纯色压暗：

```java
@Override
public void renderBackground(GuiGraphics g, int mouseX, int mouseY, float partialTick) {
    g.fill(0, 0, width, height, C_SCRIM);   // 只压暗，不模糊
}
```

> 签名已核对：`Screen.renderBackground(GuiGraphics, int, int, float)` 是 `public`，
> 覆写合法。

### 原因二：全部文字关闭了阴影

原代码 23 处 `drawString` 末尾参数**全是 `false`**（不画阴影）。深色底 + 低对比灰字 + 无阴影，
文字边缘直接和背景糊在一起。

修复：全部改为 `true`；`drawCenteredString` 本身恒带阴影，无需改动。

## 2. 画风改造：蛊界四色

蛊真人的世界是**阴湿、古旧、带血**的。界面取「墨 / 宣纸 / 朱砂 / 鎏金」四色：

| 色 | 值 | 用途 |
|---|---|---|
| 墨（压暗） | `0xD8060608` | 全屏背景 |
| 宣纸黑 | `0xF00E0D0B` / `0xF0161512` | 面板底 / 内层 |
| 暗金 | `0xFF6B5A2E` | 外描边 |
| 鎏金 | `0xFFC8A44E` | 内描边、已达、选中 |
| 朱砂 | `0xFFB33A28` / `0xFF6E2418` | 页签印记、标题竖线、滚动条 |
| 宣纸白 | `0xFFE9E2CE` | 正文 |
| 旧纸灰 | `0xFF9C9484` | 次要文字 |
| 玉青 | `0xFF7FBFA8` | 可点提示 |

具体手法：

1. **双层描边**：暗金在外、鎏金在内，模拟旧器物的包边。
2. **四角刻痕**：面板四角各画一个 6px 的 L 形折角，像装裱的绫边。
3. **页签＝朱砂印记**：选中的页签整块朱砂底 + 鎏金下沿，未选中是压暗的墨块。
4. **小标题带朱砂竖线**：每段标题左侧一道 1px 朱砂竖杠，替代原来的纯灰字。
5. **行分隔墨线**：每行底部一条 `0x22FFFFFF` 的极淡横线，把密排行文分开。
6. **流派色标**：六大类各保留自身颜色（杀伐朱红、术法靛蓝、诡道紫、身法青绿、器道赭黄、心道洋红），
   但压暗到 `0xC0`/`0x60` 透明度，作为分类条左侧的 2px 色标，不喧宾夺主。
7. **滚动条**：朱砂暗槽 + 鎏金滑块。

全部色块自绘，**不引入任何贴图**，因此不增加资源包体积，也不会和其他附属的 GUI 贴图冲突。

## 4. 回归防线

新增 `_crash3/audit_ui.py`，四条断言：

- **B1**：`render()` 内不得出现 `super.render(`（否则重新引入模糊）
- **B2**：`renderBackground` 必须被覆写，且内部不得调 `super`、必须做 `g.fill`
- **B3**：所有 `drawString` 末尾必须是 `true`
- **B4**：命中区仍只由 `layout()`/`assignRowHits()` 分配，`render` 不得改写 `rowY0[...]`

当前状态：`ALL UI CHECKS PASS`。

## 5. 文字重叠与截断（第二轮修复）

用户反馈「文字显示不全，有重叠的部分」。用脚本量了每一条真实字符串，找到 **3 处真实重叠**：

### 5.1 出身行纵向压字

> **1.1.0 变更**：出身行已整体移除，改为「成长路线行」（见 5.6）。
> 行高与两行基线的结论原样沿用：`PATH_ROW_H = 26`，行2 baseline `y+14`。

出身行高 `ROW_H=20`，却在里面塞了两行：

```
行1 baseline = y+3   → 占 y+3 .. y+12
行2 baseline = y+11  → 占 y+11 .. y+20   ← 压住行1 的 1px，且贴到行底
```

下一行紧接着从 `y+20` 开始，于是**行2 与下一行的行1 视觉粘连**。

修复：出身行改用 `ORIGIN_ROW_H = 26`，行2 baseline 下移到 `y+14`（占 14..23），
与行1 基线差 11 ≥ 字体高 9，且底部距行高还有 3px 呼吸。

### 5.2 出身行横向压字

原布局第二行同时画两段：

```
元石 1800 · 人气 +0    从 x+8 起，实测宽 103px → 到 x+111
desc 描述文本          从 x+78 起                        ← 直接压上
```

修复：**改为四列**，每列的裁剪宽度由相邻列边界推导，绝不硬编码：

```
名号(x+8) | 势力·身份(x+84) | 元石(colRq-56) | 人气(colRq) 
colRq = panelRight - 8 - 52
```

描述独占第二行整行宽度。

### 5.3 页脚戳出面板

原页脚画两行：

```
行1 baseline = listBottom+7
行2 baseline = listBottom+17  → 占 ..+26，而面板底边在 listBottom+24  ← 戳出 2px
```

修复：页脚合并为**单行**，左侧「感悟 … · 贡献 N」，右侧「M 关闭」右对齐。

### 5.4 全面加裁剪

新增 `fit(String, int maxW)`：按真实字体宽度裁剪，超宽以 `…` 结尾。
应用到所有文本：名号、势力身份、元石、人气、描述、节点名、节点描述、
觉醒名、觉醒描述、势力名、档位标题、小标题、页脚。

同时把面板从 `340` 加宽到 `400`，并统一列坐标（节点/觉醒/势力行都用 `x+96` 作为第二列起点，
成本/状态右对齐到 `panelRight-8`），视觉上三页对齐一致。

### 5.5 布局回归防线

`_crash3/audit_layout.py` —— **与 Java 同构**的几何审计。1.1.0 起数据源从
`DaotuPool.java` 改为 `DaotuGrowth.java`，用 **16 路 × 6 阶 = 96 个成长行**
（外加 42 节点 / 12 觉醒 / 6 档位）的**全部真实字符串**验证：

- H1 行内文字区间不重叠
- H2 所有文字落在面板内
- H3 同一行内基线间距 ≥ 字体高
- H4 文字底部不超出所在行高

结果：`ALL LAYOUT CHECKS PASS`（96 个成长行全部通过）。

### 5.6 成长路线行（1.1.0 新增）

十六条路线各占一行，行高 26，四列 + 一条进度条：

```
行1:  [流派名]      [当前阶名]        [第 N/5 阶]      [▬▬▬▬░░░░ 进度条]
      x+8          x+8+56           xr-152           xr-96 .. xr
行2:  [本阶描述]　[历练 1234 / 4200]
```

列宽全部由相邻列边界推导，不硬编码：

```java
colRankName = x0 + 56;
colProg     = xr - 96;
colRank     = colProg - 56;
```

- 进度条画在行1 右侧 96px 区间，高 3px：暗槽 `0x30FFFFFF` + 朱砂填充，
  满阶转鎏金。
- 左侧 2px 竖条作状态锚点：未起步无条、有进度朱砂、满阶鎏金。
- 三种文字色：满阶鎏金、有进度宣纸白、未起步暗灰。

页脚同步改为「主修路线 → 下一阶 · 历练 X / Y」，进度条占满左段。

## 6. 未验证

**没有进游戏实测**。以上为源码与字节码层面的结论。进游戏需确认：

1. 界面是否不再发糊（第一轮改动的直接目标）
2. 文字阴影是否让可读性明显提升
3. 双层描边 / 四角刻痕 / 朱砂页签的实际观感是否贴合蛊真人
4. 六个流派色标在压暗后是否仍能区分
5. **成长路线行两行文字是否清晰分离、四列是否互不压字**（第二轮改动的直接目标）
6. 长描述被 `…` 截断后是否仍能读懂（若截断过多，考虑给描述换行或加宽面板）
7. 页脚单行是否完整落在面板内
8. 点击页签、切换大类、点节点、滚动是否仍正常（`layout()` 的命中逻辑未动）
9. **1.1.0 新增**：十六条路线行的进度条是否随历练实时推进；
   十六路全部挤在一页（无分页）时滚动是否顺畅；主修路线在页脚的显示是否正确
