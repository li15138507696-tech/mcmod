# daotu v1.4.4 — 「关了自动弹窗还是会弹」的兜底修复

> 用户反馈：**关了自动弹窗，站着不动 / 打怪攒满历练时，界面还是会自己弹出来。**

## 一、先看证据

翻了整合包存档里的玩家数据（`saves/新的世界/playerdata/*.dat`，gzip + NBT 直接读）：

```
daotu        : 存在
autoPrompt   : absent        ← 整份存档里根本没有这个键
applied      : 01 (true)
confirmed    : 01 (true)
```

也就是说：**「关」这个动作从来没写进服务端存档**。服务端读不到键 → 按默认「开」处理 →
攒满照样弹。界面上的开关之所以看起来是「关」，是因为点击时客户端先本地翻转了（乐观更新），
而服务端回推的状态包要么没到、要么被随后的重绘盖掉了。

## 二、根因链

```
点击开关
  → 客户端本地 autoPrompt = false（立刻显示「关」）
  → C2S DaotuSettingPayload
  → 服务端 DaotuRun.setAutoPrompt() 写 daotu/autoPrompt
```

这条链上任何一环断了（包没到 / 服务端没处理 / 存档没写），结果都是：
**玩家以为关了，服务端仍认为开着**。而弹窗只由服务端 `promptChoice()` 决定，
所以必弹无疑。

## 三、修复：客户端拿否决权 + 服务端给回执

### 1. 客户端自己记一份偏好（`DaotuClientPrefs`）

存在 `config/daotu-client.json`：

```json
{"autoPrompt":false}
```

- 点开关时**先写本地**，重进游戏也记得；
- 收到服务端强弹（攒满历练）时：**本地是「关」就不开**。服务端那份值对不对都不影响玩家不被弹。
- 界面上的开关显示的是这份本地值，不再被服务端的旧值掰回去。

### 2. 区分「玩家按 M」与「服务端强弹」

`DaotuClientEvents` 记录最近一次按 M 的 tick，60 tick（3 秒）内算「本人主动要的」：

| 来源 | 行为 |
|---|---|
| 玩家按 M | 一定开（不受本地开关影响） |
| 服务端强弹（攒满） | 本地关着就不开 |

### 3. 顺手修掉「按 M 开地图」抢焦点

这个整合包里 `key_gui.xaero_open_map = M`，和道途的 M 撞键。按 M 时 Xaero 地图和道途
会同时触发，道途界面会把地图顶掉。现在：**如果是玩家按 M 触发的打开，而这一刻已经有别的
界面开着（地图抢先了），就不抢焦点。**

### 4. 服务端回执 + 日志（方便下次定位）

- 设置成功会给一条聊天回执：`[道途] 自动弹窗已关闭（攒满只在聊天栏提示）`
  ——**看不到这条，就说明设置包没到服务端**；
- 服务端每次攒满都会记一行：
  `[道途] <玩家> 攒满触发：autoPrompt=false（false 时只发聊天提示）`
  一眼就能看出当时服务端认为的开关值。

## 四、改动清单

| 文件 | 改动 |
|---|---|
| `client/DaotuClientPrefs.java`（新） | 客户端偏好 + `config/daotu-client.json` 持久化 |
| `client/DaotuClientEvents.java` | 记录按 M 的时刻，提供 `recentRequest()` |
| `client/DaotuClientHandler.java` | 强弹时按本地偏好否决；按 M 时不抢已打开界面的焦点 |
| `client/DaotuViewScreen.java` | 开关读写客户端偏好 |
| `net/DaotuSettingPayload.java` | 服务端回执 + INFO 日志 |
| `DaotuNet.java` | 攒满时记录 `autoPrompt` 实际值 |

## 五、验证

- `javac` 31 个源文件 exit 0
- `pack_jar.py` 打包通过（版本 1.4.4，mods.toml 与 version.properties 一致）
- 已安装 `daotu-1.4.4.jar`，与 build 产物 SHA256 一致：`B0EA5A90…A347F4B8`
- ✅ 存档证据：旧存档里确实没有 `autoPrompt` 键（这就是「关了还弹」的直接证据）
- ❌ **游戏内未实测**：客户端否决、回执、抢焦点三处都需要进游戏点一遍

## 六、如果还复现

让玩家做一次，然后把这两样发来：

1. 点开关后聊天栏有没有出现 `[道途] 自动弹窗已关闭`；
2. 日志里 `[道途] … 攒满触发：autoPrompt=?` 的取值。

有这两条就能判定是「包没到服务端」还是「存档没写」，不用再猜。
