## 二、抽选语义变了：从「随便改」到「一次定终身」

**v1.3.x**：攒满 → 系统随机自动发一个 → 玩家事后按 M 打开界面**无限次重选**。

问题很明显：既然随时能改，选择就没有分量。玩家不会认真看那 5 个选项，反正不满意再点一下就行。

**v1.4.0**：

```
历练攒满
   ↓
自动弹窗（唯一会打断玩家的时机）
   ↓
5 个候选，鼠标悬停高亮
   ↓
点一下 → 扣池、发奖、写历史、清候选
   ↓
永久锁定，只能看不能改
```

**关键设计：扣池发生在「选定」时，不在「生成候选」时。**

如果生成候选就扣池，玩家关窗不选，历练就白扣了。现在的顺序是：

1. `tryDraw()` — 池够就生成候选存进 `run/offer`，**不扣池**，弹窗；
2. 玩家不选就关窗 — 候选保留，下次按 M 还能继续选，历练一分不少；
3. `choose()` — 扣池 → 发奖 → 记历史 → 清候选 → 加抽次。

还有两个细节：

- **过期包丢弃**：玩家连点两次时，第二个包带的 `drawIndex` 与当前不符，服务端直接丢掉，不会把下一批候选误当成旧的选掉。
- **选完自动续抽**：如果池还够，`choose()` 末尾再调一次 `tryDraw()`，连续弹窗而不用手动按 M。

## 三、历练阈值：分转数递增

```
一转 144.0   二转 216.0   三转 324.0   四转 486.0   五转 729.0
```

公式：`240 × 0.6 × 1.5^(转数-1)`

- **240** 是原来的固定阈值；
- **×0.6** 就是你要求的「一转减 40%」；
- **×1.5^(转数-1)** 是「依次增加」。

**为什么要随转数涨**：高转玩家打同样的怪给的历练更多（见下节转数加成），如果阈值不变，五转玩家会一秒钟抽十几次，属性瞬间爆表。阈值同步放大，才能让「一次抽选」在整局里都保持分量。

**为什么一转要减 40%**：新手期最需要正反馈，第一世应该很快就能抽到第一个选项。

## 四、怪物分档

原来是「按最大生命线性给分」：一只 300 血的巨型怪和 30 只 10 血的小怪给的分一样，但后者要打半天。

现在按 5 档给倍率：

| 档位 | 判定条件 | 倍率 |
|---|---|---|
| 首领 | 末影龙 / 凋灵 / 类名含 `boss` | ×8.0 |
| 强敌 | 最大生命 ≥ 200 | ×6.0 |
| 精英 | 最大生命 ≥ 100，或高阶命名（王/君/尊/帝/皇/祖）且 ≥ 40 血 | ×3.0 |
| 普通 | 其它 `Monster` | ×1.0 |
| 弱小 | 动物、村民等非 `Monster` | ×0.4 |

**为什么不硬编码 656 个实体类名**：基础 mod 有 656 个生物类，硬编码名单一改版本就失效。这里用「血量 + 类型 + 类名关键词」三个廉价且稳定的信号，对未知生物也有合理默认值。

另外加了**转数加成**：`1 + (转数-1) × 0.35`。五转玩家打同样的怪给 2.4 倍历练，部分抵消阈值从 144 涨到 729 的压力。

## 六、tianfu 词条入库

从 `tianfu-1.2.18.jar` 的源码里抽了 **164 条**池子条目，最终入库 **72 条词条**。

### 为什么只取词条

tianfu 的池子有四类：

| 类别 | 条数 | 为什么不要 |
|---|---|---|
| 凡体 BODY | 20 | 会写本体 `tizhi`，那是天命的领地 |
| 十绝体 SIJUE | 10 | 同上，而且会改 `kongqiao` / 真元上限 |
| 机缘 JIYUAN | 4 | 同上，写 `zuida_zhenyuan` 会让本体反推开窍进度 |
| **词条 ENTRY** | **130** | ✅ 只给属性 / 道痕 / buff，可安全并入 |

### 130 条里为什么只剩 72 条

按「能不能在转世时回滚」筛：

| 效果原语 | 处理 | 原因 |
|---|---|---|
| `HEALTH_MULT` / `ATTACK_MULT` / `SPEED_MULT` / `ATTACK_SPEED_MULT` | ✅ 转成属性键 | 走 `run/attrs`，转世自动清 |
| `KNOCKBACK_FLAT` / `FALL_FLAT` | ✅ 转成属性键 | 同上 |
| `DAOHEN` / `DAOHEN_ALL` | ✅ 写道痕 + 记账本 | 转世按账本扣回 |
| `MOB_EFFECT` | ✅ 转成常驻 buff | 转世清 `run/buffs` |
| `CRIT_CHANCE` / `DODGE` / `LEECH` / `REDUCTION` / `REFLECT` / `OUT_FULL` / `OUT_LOW` / `REGEN_*` | ✅ 转成 `c_*` 键 | 战斗事件里读，转世清 |
| `FIELD_MULT` / `FIELD_ADD` | ❌ 丢弃 | **直接写 PlayerVariables，转世无法回滚**，会破坏肉鸽循环 |
| `XIULIAN` / `BREAKTHROUGH` / `LIANGU` / `GU_CD` / `SHAZHAO_CD` | ❌ 丢弃 | 要接本体修炼与炼蛊流水线，超出「加进池子」的范围 |
| `JUMP_FLAT` | ❌ 丢弃 | 原版没有跳跃高度属性 |

最终 72 条，效果分布：`ATTR` 12 / `COMBAT` 30 / `DAOHEN` 33 / `DAOHEN_ALL` 3。

### 怎么混进候选

候选池里现在有两类东西：

- **属性**——key 是属性键（如 `attack_damage`），选中给一小步累积；
- **词条**——key 形如 `talent:ji_wanshi_bumie`，选中给一整份大礼（可能同时给属性 + 道痕 + buff）。

每次生成候选时，从**未获得**的词条里随机抽 3 条混进去，洗牌后取前 5。所以每次弹窗大约有 1–3 个词条选项，剩下是属性。

已获得的词条记在 `run/talents`，不会重复出现（拿满时退回允许重复）。

### 一个必须记住的坑

`DaotuRunAttributes.apply` 会遍历 `run/attrs` 的全部键去挂 AttributeModifier。词条的战斗乘区键（如 `c_crit_chance`）不是属性键，会刷「未知属性键」日志。所以在遍历开头加了：

```java
if (key.startsWith("c_")) {
    continue;
}
```

## 八、模拟图暴露并修掉的三个真缺陷

沿用上一版的离线渲染器思路，新写 `_crash3/render_mock_v140.py`，按源码坐标逐像素出 PNG。

### 缺陷 1：427×240 + 5 个候选时面板戳出底边

`listH = max(ROW_H*2, min(LIST_H, avail))` 里的 `max(ROW_H*2, ...)` 是硬保护：小屏放不下也强行留 2 行，结果面板总高超过屏幕。

修复：空间不足时先压缩候选区，再把列表下限从 2 行降到 1 行：

```java
int listH = Math.min(LIST_H, avail);
if (listH < ROW_H * 2) {
    int deficit = ROW_H * 2 - listH;
    int compress = Math.min(deficit, offerH > 0 ? (offerH / 4) : 0);
    ...
}
listH = Math.max(ROW_H, listH);  // 最少 1 行
```

### 缺陷 2：▼ 箭头压在文字上

这是上一版就有的老毛病，我这次又踩了一遍：渐隐带画在 `listBottom` 附近，而半露的行也画到那里，两者叠在一起，`▼` 正好压在「特殊增益」那一行的字上。

修复：**行只画完整可见的，半行直接跳过**：

```java
int rowLimit = listBottom - FADE_H;
if (y >= listTop && y + h <= rowLimit) { ... }  // 整行放得下才画
```

渐隐带和箭头贴 `rowLimit` 下方画，永远不会碰到文字。

### 缺陷 3：护甲韧性 1.50 的条被画成满格金色

`attrScale` 原来统一按 1.0 归一，导致「护甲韧性 1.50」直接顶满，看起来像已到上限。

修复：按每个属性的实际量级给分母——护甲韧性 20、伤害吸收 16、击退抗性 1.0、幸运 5.0、跨越高度 2.0。

## 十一、诚实说明

**游戏内未实测。** 结论来自：编译通过、55 项静态审计全绿、10 种屏幕尺寸边界断言、6 张离线渲染模拟图。

需要你进游戏确认的：

1. **弹窗时机**——攒满立刻弹窗会打断战斗。如果你觉得烦，我可以改成「攒满只提示、按 M 才弹」。
2. **词条数值**——tianfu 的词条是按「天命开局一次买断」设计的，数值偏大（如「极·万世不灭」生命 +150%）。放进每局可重复抽的池子后可能偏强，需要你实测手感。
3. **怪物分档**——血量阈值（100 / 200）是我估的，基础 mod 的生物血量分布我没实测。如果大部分怪都在 100 血以下，精英档会形同虚设。
4. **模拟图字体**——用微软雅黑 9px 近似 MC 默认字体，真实字形可能差一两像素。偏挤的行会被 `fit()` 裁成 `…` 而不是压字。

另外：`▲` `▼` `◆` `…` `×` `·` 都在 MC 默认字体里，但 `✦` `▸` `◉` `○` 不一定——我把 `✦` 换成了 `◆`、`▸` 换成了 `>`，避免显示成方框。
